# oracle — the CyborgPL reference interpreter

The executable specification. A tree-walking interpreter in Rust that
implements exactly what `design/` has decided, refuses everything undecided
with a message that says so, and is deliberately slow, small, and obvious.
Its job is to keep the prose honest: if a note in `design/` and this program
disagree, one of them is wrong, and it is usually the note.

Not the compiler. Not the prover. No LLVM. See `design/compiler-verification.md`
for where it fits.

```
cd oracle
cargo build
./target/debug/oracle ../examples/scores.cy
./target/debug/oracle ../examples/geometry     # a Kit directory: kit.cy + modules
cargo test          # every examples/*.cy (or Kit directory) must match its .out;
                    # every tests/reject/*.cy (or directory) must fail with its .err
```

## What it enforces

Everything in `design/syntax-sketch.md`, `types.md`, `operators.md`,
`functions.md`, `control-flow.md`, `ownership-syntax.md`, and the `MAIN`
entry point — see `tests/reject/` for one program per rule. Highlights:

- quoted names are variables; function names are bare; keywords are reserved in bare positions — a keyword-named `fn` is reached only by path (`my.to[…]`, 2026-09-19; the root is `my.` since 2026-10-06, and `limb.` is refused naming it)
- `let 'x' := v;` / `let 'x': T = v;` — `let` again since 2026-10-02 (none 2026-09-25 to then); `:=` only without a type, `=` only with one; `mut` / `immut` / `!mut` between `let` and the name, `!$` before those (cannot be shadowed); changing is `change 'x' = v;` (a bare `'x' := v;` or `'x' = v;` is refused, naming `let` or `change`, as are `var`, `func`, `loop.while`, `else.if`, `loop.temp.for`)
- `&'x'` / `&mut 'x'` are accepted wherever `lend 'x'` / `lend.mut 'x'` are (call site, `.field`, `[i]`), and `&'x': T` / `&mut 'x': T` wherever `lent` / `lent.mut` are (parameters, `fn[…]` types), silently since 2026-10-02 (from 2026-09-21 each `&` printed `What are you? Rust programmer or Claude?`); `std::this_will_print_the_useful_numbers.this_will_go_to_the_standard_output` is `print.useful.stdout` (both 2026-09-21)
- `fn name ['a': i32, lent 'b': str.utf8, lent.mut 'c': list[i32]] -> i32 { }`; an owning parameter has no keyword; the return type is `-> T` after the parameters; `...'rest'` (last only) collects the remaining arguments, each checked as if bound to that parameter (2026-09-19)
- `std::print.format.stdout/stderr[fmt, …]`: C escapes and `%` formatting, checked against the arguments (type, count); `%u`, `%p`, `%n` refused; a non-literal format needs `nocheck` (2026-09-22)
- `concur [.detached] [with […]] { … } [otherwise …]` / `concur f[…]`: tasks with explicit captures (a detached task may not lend); a block waits for the tasks it started; a task's failure lands on its `concur`'s `otherwise` (required when the body can fail); `return`/`break` inside a task refused
- `channel[T]` / `channel[T][0, N]`, `channel.send` (a value is given, never lent), `channel.take … otherwise` (fails `closed` when nothing can ever send), `whichever { 'v' from lend 'c' { } … } otherwise` (fails `closed`); `std::time.after/every` are channels, `std::time.wait` a no-op; duration literals `5 seconds` (nanos…hours, singular/plural) with `== < + - x` (2026-09-22)
- an untyped list still has an element family (what is in it): storing a bin into a list of integers is refused, as into a declared `list[i32]` (hole found by the compiler session, 2026-09-22)
- `list.slice` / `array.slice` with bare positions, 1-based and inclusive, owning the elements; out of range and a backwards span are check sites (2026-09-23)
- `bin` is 16/32/64 — `f128` is refused by name (2026-09-23); `d32/64/128` are exact decimals (2026-09-29, `examples/deci*.cy`); `std::uenr` waits for the std kit
- plain integer math (`+ - x xx`) is **exact, and checked where the value lands**: a typed declaration, a `change`, an argument, a return (owner, 2026-09-23). `'v' > ('v' + 'v')` on an `i8` of 112 compares 112 with 224. In between, a value no 64-bit type holds (below `i64`'s minimum or above `u64`'s maximum) is a check site; bare numbers alone are worked out exactly. This reverses the morning's "checked where it happens" (seed 23), which was a reading, never a ruling
- `shl` with no width anywhere (a bare literal straight into a print) is refused, as operators.md has it; the oracle had computed it at 127 bits until compiler claude found the gap (2026-10-06)
- a shift's, `not.bit`'s and a wrapping operator's width comes from any operand whose type is known — a declared name, a `to.T[…]`, either side of an operator, or the type the value is being stored into; only a bare literal with no context has none (2026-09-23)
- a `for` range's step is its own signed number: `for 'i': u64 in range[3, 1, -1]` is legal, and `range[3, 0, -1]` stops at 0 without underflowing (2026-09-23, fixed after the verification session found the oracle refusing it)
- `simd[T, N]`: the target's shapes only (the oracle's target is ARM64's 128-bit registers, so `simd[u8, 16]`, `simd[i32, 4]`, `simd[f64, 2]`, …); ordinary operators lane by lane, scalar-with-vector broadcasting, comparisons giving `simd[bool, N]` (and so refused as a condition); `simd.fill` (lane count from the declared type) / `load` / `store` (both check the bounds) / `all` / `any` / `max` / `min` / `sum` (2026-09-22)
- `map[K, V][lo, hi]` bounds the entry count (checked on `set`/`remove`; `map.length` is `u64[lo, hi]`); `set` checks the key and value against K and V (2026-09-22)
- `map["ann" = 5551, …]` literal; `map[]` refused (`map.empty`); a duplicate key in a literal refused (2026-09-22)
- `map.keys/values/pairs[lend 'm']` give lists in insertion order (`pairs` as structs with `key`/`value`); `map.ordered` / `map.unordered` variants, and walking a `map.unordered` is refused (2026-09-22)
- `map[K, V]` with `map.empty/length/has/get/set/remove` (`get`/`remove` fail `missing`, `otherwise` required; `set`/`remove` need `lend.mut`); keys by structure, or by a type's own `op ==`/`fn hash` — and then equal keys hashing differently is a check-site error on the comparison that exposes it; functions, pointers and maps refused as keys (2026-09-22)
- `str.utf8[lo, hi bytes|points|graphemes]` — a length-bounded text; the unit is required; assignment and `++` are checked against it; `to.str.utf8[…bound…][v]` fails `out_of_range` (2026-09-22)
- an `extern.C fn` with a ranged return (`-> u64[0, 10]`) can fail `out_of_range` (an `otherwise` is required; `nocheck` does not remove it); a plain-return extern still cannot fail (2026-09-22)
- `extern ['mut'] 'x': T;` — a C global (`extern let` until 2026-09-25), C-shaped, no value; reads and writes are nocheck sites; a read-only one cannot be written; no verbs; emulated as zero until written (2026-09-21)
- `char.code[c]` (point/byte → number; grapheme refused), `char.point.from_code[n]` / `char.byte.from_code[n]` (fail `not_a_char`), `to.char.<unit>[text]` (fails `not_one_char`), `to.char.<unit>[char]` down (fails `not_one_point` / `not_one_byte`) and up (no `otherwise`); `to.i32[char]` and `to.char.point[number]` refused; a char literal takes its declared unit (2026-09-21)
- a module (block or file) and a struct/enum/interface with the same name in one kit are refused (2026-09-21)
- `to.i32[…]` of a bin fails `not_whole` unless the bin is whole (an `otherwise` is required); `std::round` / `floor` / `ceil` / `trunc` round a bin to a whole bin (2026-09-21)
- `list.remove[lend.mut 'xs', pos: i]` hands the removed element back (a value, or dropped as a statement); `list.append` used as a value is refused; `give 'xs'[i]` stays refused (2026-09-21)
- `...'xs'` in a call unpacks a list into the variadic part; refused when the list's length is not known here (the oracle knows: a literal list, `list.empty`, a bounded type, a bundle — and forgets after `append`/`remove` on an unbounded list), when the function has no variadic, when it would land on a fixed parameter, or outside a call; owned elements into an owning variadic need `...copy` / `...give` (give empties the list), a verb on plain elements or into a `lent ...` is refused (2026-09-21)
- `list[T][lo, hi]` is a length-bounded list: construction, assignment, `append` and `remove` are checked against the bound; its `list.length` is `u64[lo, hi]`; `array[T][…]` is refused (2026-09-21)
- `list.length` / `array.length` are `u64`: an untyped `:=` from one takes that type, so a later negative assignment is refused (2026-09-21)
- `[ ]` is written only where it builds: a list (comma separates values), a call's arguments, a struct construction, an index, `range[…]`; a single expression stands bare (`'x' := 1000;`, `if 'a' == 'b' { }`); two values side by side are an error
- `++` joins text (2026-09-19): both sides must be text (`to.stored.str.utf8[…]` / `to.useful.str.utf8[…]` convert; a bare `to.str.utf8[…]` of a number, `bool` or enum case is refused naming both, 2026-10-02, while text, characters and bytes stay bare; a bin or `brain16` into a `deci` writes `to.stored.`/`to.useful.` too, 2026-10-02); `to.<type>[value]` converts — text→number fails with `not_a_number` and takes `otherwise`, narrowing is a check site, bin→int / bool / char / list / struct are refused; precedence below `+ -`, above comparisons; `print`/`print.useful` take any number of comma-separated values and render each (stored / useful)
- precedence as mathematics has it, parentheses required where it has no settled answer (`6 div 2 x 3`, `mod` beside anything, chained comparisons, `not` beside a comparison)
- `x xx + - / mod ++ == !== < > </== >/== and or not`, wrapping `+~ -~ x~ xx~` (the oracle wraps at the left operand's declared width — a typed variable — and refuses otherwise); bitwise `and.bit or.bit xor not.bit shl shr` (parenthesise beside any operator; `not.bit` and `shl` overflow need a declared width); `!=`, `>=`, `<=`, `--`, `+=`, `-=` are refused with a pointer to the right spelling; `*`, `^`, `%`, `&`, `|`, `!` are refused unless declared with `op`
- no implicit conversion between numeric families; a bare literal adopts its
  context's family; typed widths are range-checked
- `give` / `copy` / `lend` / `lend.mut` at the call, nothing / `lent` /
  `lent.mut` at the parameter, and they must agree; a bare owned variable
  cannot be stored; a given variable is dead until reassigned
- the default check tier: every landing and every 64-bit limit is checked, and
  every division zero-checked, because there is no the prover here to remove them
- `check <stmt>` / `nocheck <stmt>` / `check { … }` (2026-09-19): the oracle runs the check anyway; a `check` whose site fires reports the counterexample value, a `nocheck` whose site fires reports the lie; refused on a fn/struct/const/module, inside a value, at the top level, or doubled
- `print` shows the stored value (full binary expansion), `print.useful` the useful one (the borrowed C/Rust prints of 2026-09-19 were removed 2026-09-20 and are refused by name)
- strings are exactly their characters; only `\"` and `\\` escape; `"\n"` is two characters, the newline is the bare `\n` (2026-09-19)
- comments: `#`, `#wl`, `#Nl`, `#Nld`
- `MAIN { }` is a block; `std::exit[n]` is `u8`-checked
- modules (2026-09-19): a kit directory's `kit.cy` is the root, every other `.cy` a module (directories nest), `module name { }` blocks nest; names lowercase ASCII, not device names; bare = this module, dotted = relative, `my.` = root (`limb.` until 2026-10-06); visibility nothing / `pub.kit` / `pub` on fn, struct, const, module, checked along the whole path (`pub` and `pub.kit` behave alike inside one kit); `mod x`, `module x;`, MAIN outside the root, a file-and-block module are refused
- failures (2026-09-19): `-> T or fail[a, b: type]`, `fail a;` / `fail b[v];`, `call[…] otherwise value | return … | fail | { a { } b 'v' { } }`; the caller's side is checked before the call runs; `examples/failures.cy`
- FFI (design/ffi.md, 2026-09-20): `extern.C fn …;` (C-shaped types only, no `lent`, no `fail`, no body), a call is refused outside `nocheck`; `ptr[T]`/`ptr.mut[T]` only in extern signatures and `layout.C` fields, a `lend`/`lend.mut` becomes the pointer; `ptr.read/write/at` are nocheck sites (past-the-end or null under nocheck = "lied"), `ptr.is_null` is not; `ptr.null`, C's NULL (2026-10-21), a value going only where its pointer type is known, a `:=` holding only it (alone or every list item) refused; `layout.C struct` fields must be C-shaped; `size.of`/`align.of` are C's sizes; `nocheck inline.ASM { raw } with ['v' -> x0, 'n' <- x0, clobber x16];` is parsed and checked, then refused to run; emulated libc: write, exit, getenv, strlen, malloc, free, qsort (calls a Cyborg comparator); a callback must be capture-free and C-shaped (2026-09-21); `ptr[T]` may appear in any fn signature, not in a variable declaration
- text (design/strings.md, 2026-09-20): `str.bytes/points/graphemes[lend 's']`, `str.each.<unit>[…]`; `str.length`, `'s'[…]`, `<` on text, and a bare `for` over a text are refused; emulated std: `std::str.split/join/contains/starts_with/ends_with/trim/upper/lower/replace`, `at.<unit>` and `slice.grapheme` (fail out_of_range), `find.grapheme` (fail missing)
- enums (design/enums.md, 2026-09-20): `enum S { a, b: i32 }`, `S.a`, `S.b[1]`, `match 's' { a { } b 'v' { } }` with every case covered; an enum is owned; `==` works; `match` on a non-enum is refused
- integers of any width (2026-10-03): `!std.intN` / `!std.uintN` (Rust-style `!std.iN` / `!std.uN`) up to 8,388,608 bits; values past i128 are the oracle's own big numbers (`src/bigint.rs`, sign and 32-bit kits, tested against i128 and Python); in between, the widest operand's width, at least 64 bits; wrapping at 127 bits and up is on big numbers (which also fixed `u128` wrapping, which had wrapped at 2^127); bitwise operators, shifts and `not.bit` on big numbers too, at the type's true width (which also let `u128` shift by 127 and flip all 128 bits); not built: wide integers as SIMD lanes
- the operators are words (2026-10-03): `plus`, `minus` (a negative keeps `-`), `times`, `plus.wrap`/`minus.wrap`/`times.wrap`, std's `pow`/`pow.wrap` (bare or `std::pow`, above a negative, right pair first, as `xx` was); a `precedence.low_first`/`high_first` block gives a file's operators levels (read from every file of the program, dependency kits' too, before anything else is parsed, so a kit's levels apply wherever its operators are used; two kits giving one operator different levels is refused; two kits' operators in one gap are not yet checked); `+ - x xx +~ -~ x~ xx~` refused naming the word; `op plus` as a value and for a type
- every division says how it rounds (2026-10-02): `div.floor` / `div.ceil` / `div.trunc` / `div.near` (a tie to even), and `mod.X` what `div.X` leaves over, on every number family; bare `div` / `mod` refused. On integers every quotient is whole; on a bin, `brain16` or `deci`, `div.near` is ordinary division and `floor`/`ceil`/`trunc` give a whole quotient, so `mod.near` is refused there. A `mod.floor` that rounds up to the divisor is `0`
- custom operators (design/operators.md, 2026-09-20): `op <+> ['a': V, 'b': V] -> V { }`, `op dot […]`, `op ** [give 'a': V, 'b': f64] -> V { }`; a run of `! % & * + - / < > = ? @ ^ | ~` is one operator; no precedence (parenthesise); operands lent unless `give`; the language's operators and near-misses cannot be redefined; an op is never called with `[…]`
- `brain16` (also `bfloat16`, `bf16`), the brain float (2026-10-02): its own family; each operation done at 32 bits and rounded to the nearest brain16; literals and `to.brain16[…]` round to the nearest; `to.f32`/`to.f64` of one exact, `to.f16` a check site past 65504
- `*0.1`, "exactly this" (2026-10-02): a deci, of the width the place wants
- Rust's number names are aliases wherever a type is written: `i8`–`i128`, `u8`–`u128`, `f16` `f32` `f64` (2026-10-02); `usize`, `isize`, `String`, `f128` are refused naming what to write
- generics (design/generics.md, 2026-09-20): `<T>` in fn signatures, struct fields, enum cases; every blank announced after the name with what it accepts (`fn max <T>: Number […]`, `struct Pair <A>: any <B>: any`, lifetime groups after a `|`, 2026-10-02), `Pair[i32, str.utf8]` filling them in that order and checked against the bounds; a `<T>` binds to the first value's kind and every later one must match; `size.of[<T>]` and `<T>` in an extern are refused
- interfaces (design/interfaces.md, 2026-09-20): `interface I <T> { fn …;  op …; }`, or a list of types one per line, or both (2026-10-02; a listed type matches by family, `i32` admitting any integer), `<T>: I and J` bounds checked when a call fills the blank, `V satisfies I;` claims checked at load; the language's operators may be defined for user types (`op < ['a': V, 'b': V]`), picked by the left operand's type; verbs on a `<T>` value are allowed and do nothing for a plain type
- input and range types (design/input.md, 2026-09-20): `std::input.line[]` / `.all[]` read stdin, fail `closed`; `i32[0, 100]` / `f64[0.0, 1.0]` types checked on every store (a site), `to.i32[0, 100][…]` fails `out_of_range`; bounds must match the family and be ordered; ranges cannot cross to C
- **powers** (owner, 2026-10-07): a manifest's `powers = [cyjet::power.c_calls,]` lists what its kit uses, and the program's `deny = [cyjet::power.c_calls.except["write"], cyjet::power.inline_assembly.for["fastjson"],]` takes powers away (a dependency's `deny` is read but only the program's applies). Uses found: `inline.ASM` → `inline_assembly`; a call to an `extern.C fn` → `c_calls.functions[name]`; a C variable's name → `c_calls.variables[name]`; `ptr.read`/`ptr.at` → `raw_memory.read`, `ptr.write` → `raw_memory.write`, `ptr.cast` → `raw_memory.cast`; `!check` → `vouch`, `NO_FUCKING_CHECKS` → `vouch.c`; an `op` whose every operand is built-in → `operators_on_builtin_types` (one operand: `prefix_operators`). Each use is checked, in order: granted (the base grants the first three to every kit; IEG, when listed, the rest), listed (a listed power covers a use when its path is a prefix and its things, if any, name the use's), not denied (path prefix, `.for` naming the kit's prefix, `.except` not naming the thing). A kit with no `CyJet.cyr` is not checked. All found before running, from the parse. `examples/power_deny_except`, reject tests `power_*`, `op_power_not_granted`
- **the 2026-10-07 revision** (owner; table in `design/revision-2026-10-07.md`): one spelling per thing and every other refused by name, MTM being gone (`-->` → `->`, `!mut` → `immut`, `!check` → `no_check`, `!cheat` → `no_cheat`, `!$` → `no_shadow`, `! 'x'` → `not 'x'`, `==` → `equal_to`, `!==` → `not_equal`, `</==` / `>/==` → `at_most` / `at_least`, `!std.` → `not_std.`, `std::` → `std::`, `\n` → `newln`, `auto_newline` → `auto_newln`, `giveS` → `is`, `&` → `lend`/`lent`, Rust's number names, `inline.Assembly` / `inline.S`); labels `range[from, to, by]`, `pos` on every index and position, `list.fill[value, count]`, `simd.fill[value]`; a case's value says `is`, a nested match that is the value `is match …`; a print goes to stdout unless `.stderr`; `format[…]` makes text; every parameter and return typed (an untyped variadic still keeps each argument's own type, an open question); `fn name <T: any, U: X> [@x, @y] [params] -> T`, `lent @x` spaced, a returned borrow naming its group when it borrows two or more inputs; `#strict` refused; the new limbs TAS, AI, WSMW, Money, UniTect, CAPS registered and their features (and ASP's ranges) refused in a kit that does not list them. The lexer reads the new words into the tokens the interpreter always used (`no_check` is `nocheck` inside, `equal_to` is `==`), so the interpreter barely changed; messages name the new words (`op_words`). Internally the language is still called the base in comments: the rename is on hold (owner).
- code for one target (owner, 2026-10-06): `on.target aarch64-macos { … } else on.target.chip x86_64 { … } else on.target.os windows { … } else { … }`, chosen when compiling against the oracle's target, `aarch64-macos`; a branch ruled out is parsed but never checked or run (`else on.…` continues a chain, `else if` is refused); around items at the top level too, keeping only the chosen branch's items. `on.machine.chip aarch64 { … } else { … }` asks the machine the oracle runs on (Rust's `is_aarch64_feature_detected!`: neon, sve, sve2, aes, sha2, sha3, crc, lse, dotprod, fp16, bf16, i8mm), needs IEG, and only inside a body. `on` is a keyword. Provisional, design claude's: the lists of chip and OS names (aarch64, x86_64, x86, arm, riscv64/32, wasm32/64, powerpc64(le), s390x, mips64, loongarch64; macos, ios, linux, android, windows, freebsd, netbsd, openbsd, wasi, none) and of features. Not built: a minimum (`on.target.os macos 15`, `on.target.chip aarch64 sve`), since how a build names the oldest OS and the chip features it needs is not decided. `examples/on_target.cy`, reject tests `on_*`
- **Another kit's names always take its path** (owner, 2026-10-22; `design/kits.md`): std's too (`std::print.useful`, `std::list[i64]`, `std::list.append`, `std::casing.tr`, `std::duration`); this kit's own names and the base's stay bare; a kit's operators, word and glyph, take an optional path (`'a' greet::merge 'b'`, `'t' greet::<+> 'u'`); another kit's enum value is `greet::Tone.loud`. The `bare.` marks are refused everywhere (std/'s stopgap ended the same day, when std claude took its marks out). **`use <path> as <name>;`** at a file's top renames a path for that file, written into the tokens before parsing, all `use`s in one pass; `as` required, the path another kit's, nothing declared under the name. `examples/use.cy`, `examples/uses_paths`, reject tests `std_*_needs_path`, `kit_name_needs_path`, `use_*`
- std is listed like any kit (owner, 2026-10-06): `cyjet::dep[id = "fff4302d…d6761936", version = "2026-10-06T12:57:14+07:00"]` (std's ID and the version the oracle stands in for; another version or listing it twice is refused). **A kit whose `CyJet.cyr` does not list std reaches none of std**: every `std::` path, the operators (`plus`, `minus`, `times`, the `.wrap`s, `pow`, `div.X`/`mod.X`, the comparisons, `and`, `or`, `++`, the bitwise ones) and the one-operand `-`, `not`, `not.bit` are refused naming the line to add (`and.then`/`or.else` stay, the base's). A program with no `CyJet.cyr` (a lone file, or a directory without one) gets the full package, as the machine's install would give it. **A kit whose `CyJet.cyr` does not list a limb reaches none of its words** (owner, 2026-10-05: "Limbs should say what cores they are built for"): ASP's `to.` and `check`, IEG's `nocheck` and `NO_FUCKING_CHECKS`, Genny's generics, `interface` and `satisfies`, MCPS's `concur`, `whichever`, `channel` and `for para`; MCPS without IEG is refused (owner: "Needs IEG, not std"). Growing lists, maps and text operations are std's too (owner, 2026-10-06): without std, `list`, `map` (as types, literals or operations) and `str.bytes`/`str.split`… are refused; fixed arrays and text literals stay (reject tests `no_std_list`, `no_std_map`, `no_std_text`). and ASP's raw form `to.i8.bits[…]` reads a whole number's bits as the type's (`to.i8.bits[128]` is -128, `to.u8.bits[-1]` is 255); a value the type's bits cannot hold, as signed or unsigned, is refused (owner, 2026-10-06: "`a`"), and `.bits` on a non-whole-number type is refused as undecided (`examples/to_bits.cy`). **Without ASP a whole-number literal is a bit pattern** (owner, 2026-10-06): landing in a typed integer (a declaration, `change`, an argument, a struct field, a `return`) it takes the type's bits, read as signed for `intN` (`128` in an `i8` is -128, `40000` in an `i16` is -25536), and one wider than the type's bits is refused (`256` in an `i8`; owner: "`a`", "Signatar's, then"). - **The oracle's task schedule**: a task runs when something waits on it (a `take`, a `whichever`) or when its block ends, in source order; a sender never waits (the oracle cannot suspend a task mid-body, so a hand-off or a full bounded channel just queues — the waiting is unobservable in output); time never passes unless nothing else can run, and then a timer channel fires at once. | Grapheme counting is an approximation (combining marks, ZWJ, variation selectors, skin tones) | `interp.rs` `grapheme_count` | The real runtime needs UAX #29 |
| A pointer into a lent `str` reads its UTF-8 bytes and yields 0 one past the end; a normal struct's `size.of` uses C's rule | `interp.rs` `ptr_op`, `size_align` | The oracle has no memory; the prover's real layout is not modelled |
| `ptr.cast[T]` relabels: the oracle's pointers carry no element type and its memory is a list of values, so a cast never reinterprets bytes (a `Point` written through a cast pointer reads back as that `Point`, never as its bytes) | `interp.rs` `PtrCast` | The oracle has no memory |
| A `deci` literal with too many digits for its type is refused when the run reaches it, after any earlier output; the design makes it a compile error, and kayo refuses the program up front | `interp.rs` | The oracle types a literal only where it lands (check claude, 2026-09-30) |
| A file module is public; a directory with no `.cy` of its own is an implicit public module | `main.rs` `load` | A file has no line to carry `pub.kit`; open in `design/kits.md` |
| `shl`/`shr`/`not.bit` on an exact plain sum of mixed sizes take the left operand's declared type | `interp.rs` bitwise branch | Wrapping was ruled (write the size, 2026-09-23); shifts were not asked |
| `xx~` wraps at the base's size, and its exponent's size does not count as mixing | `interp.rs` wrapping branch | By analogy with a shift's count; the owner ruled mixing for values, not for a power's exponent |
| `*0.1` under `:=` is a `d64` | `interp.rs` `Exact` | The design leaves the width to the prover, which the oracle does not run |
| A `brain16` literal in a list is rounded from its 64-bit value, not straight from its digits (a declaration rounds from the digits) | `interp.rs` `elem_literal` | Differs only on a rare tie |
| A bin operation on two different widths (`f32` with `f64`) rounds at the wider | `interp.rs` `bin_width` | Mixed bin widths were not asked; the owner ruled per-step rounding at the values' width |
| A C enum or ranged value coming from C (a return, a lent `ptr.mut`, `ptr.read`, a C variable) is checked and fails `out_of_range` — not exercised, since no emulated libc function hands one over; `to.Key[…]` and the callback rule are | `interp.rs` | The rules are decided; the oracle runs no real C |
| Text → bin also takes a leading `+`, and refuses `_` grouping, `.5`, `5.` and surrounding spaces | `interp.rs` `bin_text` | The owner ruled sign, digits, fraction and exponent; these edges were not asked |
| A list/array mismatch is caught where the source's type is declared (a variable, a call's return, a slice, a conversion); a field read is not traced | `interp.rs` `coll_kind` | The oracle's limit, not the rule |
| `return lend 'x'` and `return f[…]` (a call handing back a borrow, 2026-10-02) are checked without a call; a borrow returned through a local or another lend is checked when the function runs, and a chain of calls is followed 8 deep | `interp.rs` `check_returned_borrows` / `call_deps` | The oracle's limit |
| A borrow, a change of what it borrows, then a use of the borrow is refused on every path when read top to bottom (`lend 's'` or a `-> lent@x` call); without `@x` a call's result borrows whatever its body may hand back on any path; a loop's second trip round is caught only on the path the run takes; a stale borrow is refused where it is next used; a change to a field borrowed with `lend 'x'.f`, and a `for` over an element's lend, are not traced | `interp.rs` `wrote` / `stale` | The oracle's limit: the prover refuses on any path, at compile time |
| A deci range's bounds are held as bins, so a deci128 within a bin64's precision of a bound may be judged inside | `interp.rs` `check_type` | The oracle's limit |

## Not implemented because not designed

Whatever `design/` has not decided is refused with a message naming it —
e.g. `inline.C`, a C function as a value, a bin NaN or infinity into a
`deci`. The std kit is not written yet (owner, 2026-09-30: a new session
will write it, not soon), so `std::` holds only the few names above; the
rest, `std::uenr` among them, are refused.
